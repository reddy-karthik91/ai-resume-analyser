# API Response Format

This document specifies the standard JSON response format for all REST API endpoints. Establishing a unified payload envelope simplifies parsing in the Angular frontend client, standardizes validation error reporting, and provides consistent request tracking.

---

## The Standard Envelope

Every API response payload returned by the Flask backend must follow this contract layout:

```json
{
  "success": true,
  "message": "User-friendly context or status message description.",
  "data": {},
  "errors": null,
  "timestamp": "2026-07-03T18:32:37Z",
  "requestId": "5c4d68e2-f674-4b53-a74e-862d26d013bc"
}
```

---

## Field Specifications

### 1. `success` (Boolean)
* **Description**: Indicates whether the requested operation was completed successfully.
* **Usage**: The frontend interceptor maps this flag to determine if downstream service observables should emit success sequences or error prompts.
* **Values**:
  * `true` for successful operations (e.g. `200 OK`, `201 Created`).
  * `false` for failed validations, exceptions, or timeouts (e.g. `400 Bad Request`, `500 Server Error`).

### 2. `message` (String)
* **Description**: A short description summarizing the operation result.
* **Usage**: Provides a fallback message to display directly in toast notifications (`ngx-toastr`) or alerts.

### 3. `data` (Object / Array / null)
* **Description**: The primary response payload content containing requested entities.
* **Usage**:
  * For queries returning resource lists, this will be a list of items or a paginated object.
  * For detail pages, it will be a single dictionary object.
  * For operations that do not return resource data (e.g., delete actions), it should be set to `null` or `{}`.

### 4. `errors` (Array / null)
* **Description**: A list containing structured error logs for validation or form failures.
* **Usage**:
  * Set to `null` for successful requests.
  * When `success` is `false`, this contains objects describing specific fields that failed constraints, e.g.:
    ```json
    "errors": [
      {
        "field": "resumeFile",
        "issue": "MIME type must be application/pdf."
      }
    ]
    ```

### 5. `timestamp` (String)
* **Description**: ISO-8601 formatted datetime string indicating when the server processed the response.
* **Format**: `YYYY-MM-DDTHH:MM:SSZ` in UTC.

### 6. `requestId` (String)
* **Description**: A unique UUID version 4 identifying the request context.
* **Usage**: Generated by backend logging middleware for tracing transactions through server logs, troubleshooting bugs, and audit monitoring.
